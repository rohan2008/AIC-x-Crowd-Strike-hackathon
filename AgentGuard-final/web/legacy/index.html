Agents and permissions

COORDINATOR

Supervisor

Assigns the support task, asks for a review, then decides whether to send the draft. It cannot look up customers or change tool permissions.

agentguard/supervisor.py
SPECIALIST 01

Support agent

Looks up customer details and writes a draft. Returns the recipient, message, and records it used. It cannot send replies.

agentguard/agent.py
SPECIALIST 02

Security reviewer

Checks the draft and lookup history, then recommends sending or stopping. It has no tools. If support has already read another customer’s data, the reviewer can report it but cannot undo it.

agentguard/reviewer.py
SPECIALIST 03 · TEST ONLY

Red-team agent

Writes attack variations based on the current ticket. It has no access to customer records or tools. Test the variations individually; they are not added to the eight standard tests.

agentguard/redteam.py
CODE · NOT AN AGENT

Firewall gateway

Checks tool permissions, limits lookups to the ticket’s customer, removes private fields, and binds replies to the verified sender. Outbound inspection catches known private markers in plain text or common encodings, plus common credential formats. Agent approval cannot bypass these checks.

agentguard/sandbox.py · defense.py · firewall.py
CODE · NOT AN AGENT

Tests and logs

Runs each ticket three ways and records what happened: data read, replies written, actions blocked, and errors. An unauthorized read still counts even if the reviewer stops the reply.

agentguard/evaluation.py
How the agents run

Live mode uses the same model for each agent, with separate prompts and conversations. Simulation runs local scripts instead. The reviewer-failure switch works only in simulation.

This demo uses two tools and fake records. Outbound checks cover known markers in plain text, Base64, hex, and URL encoding, along with common credential formats. They can miss rewritten or otherwise transformed secrets and do not provide production authentication.
